# If the connection fails

The main host should have a recent PRIVATE recovery export downloaded locally.
It contains hidden roles, ballot records, group phases, pending outcomes, mission
instructions and scores. It excludes PIN hashes and login tokens. Never open it
on the extended projector display or send it to players.

1. Pause the evening verbally. Tell NCOs which actions are now on paper. Do not
   let some groups keep submitting online while others count paper votes.
2. Use player numbers and group names from the recovery record. Keep role lists
   and confirmed pending victims with the authorised NCO only.
3. For a ballot already closed in the export, preserve that result. For an open
   ballot, check the exported current votes, or explicitly restart a paper ballot
   for that group. One vote per active player, no self vote, same-group targets.
4. Record absent submissions as abstentions. Use one runoff for a tie and an
   explicit host draw after a tied runoff. Zero votes never causes a random loss.
5. Mark confirmed pending murders separately from public eliminations. Do not
   select replacement victims after a shield block or redundant murder. Unconfirmed
   secret objectives require physical NCO verification before their deadline.
6. Record every later action with time, group, player number, reason and the NCO
   who confirmed it. Score missions separately from deduction results.
7. Continue physical missions after elimination. Follow the original results,
   clear-up and parade deadlines. Do not reroll roles or invent a replacement event.

Recovery exports are snapshots. If a server response was lost after committing,
the export may be behind. Before returning online, the host must compare current
server records with the paper log and resolve discrepancies with staff. There is
no automatic paper-import function. Do not press old reveal buttons blindly or
create replacement players to reconcile a mismatch. If reconciliation would risk
two conflicting games, finish the remaining evening on paper.

Store recovery files according to staff arrangements, then remove them when no
longer needed. Event deletion removes game records, not copies of downloaded exports.
