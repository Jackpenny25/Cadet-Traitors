# NCO rehearsal checklist

Use a separate rehearsal event. Never seed practice accounts into the live event.
The rehearsal link is the website URL with `?practice=EVENT_UUID`; its projector
generates that QR automatically. Returning to the normal website selects the live
event. Use distinct browser profiles or separate phones for separate accounts.

Record the device, network, expected result and actual result for each check.

| Check | Evidence to record |
| :--- | :--- |
| Empty live setup | No practice names or roles appear in the real roster |
| Two real phones register and join | Same event, stable numbers/groups after refresh |
| Host starts a mission and pauses it | Other phones update without a refresh; countdowns agree |
| Wi-Fi and mobile data | Repeat with several phones behind the same Wi-Fi address |
| Role privacy | Faithful network responses contain no other secret roles or targets |
| NCO boundaries | NCO cannot read or control another group, even with a crafted request |
| Public projector | Responses contain no pending victim, objectives, private messages or credentials |
| Votes and refresh | Changed vote survives refresh; closed ballot rejects a late request |
| Runoff | New ballot ID; old requests are rejected; only tied candidates are eligible |
| Tied runoff and empty ballot | Explicit random draw only after tied runoff; empty vote needs reopen/skip |
| First murder and shield | One outcome per opportunity; no replacement after a shield block |
| Supervised objective | Reporting alone does nothing; physical NCO verification is required |
| Pending outcome | Victim stays publicly active; acting Traitor’s banishment does not erase confirmation |
| Redundant murder | Banished pending victim is not replaced or eliminated twice |
| Eliminated phone | No voting, new private messages, objectives or murder actions |
| Recovery on another phone | New PIN works, old sessions stop, same player/role/vote remains |
| Lost connection and background tab | Latest authorised state returns; no false saved receipt |
| Concurrent organiser actions | Two devices submit closure/reveal together; only one result is applied |
| Scores and corrections | Within mission maximums, reasons recorded, scores separate from victories |
| Projector QR | Scan on both iPhone and Android; correct deployed URL, no code required |
| Extended display | Only public projector appears on the public screen |
| Revoke board link | Old link stops, new projector link works |
| Final results | Three banishments or early win per group; no parity rule; roles released only deliberately |
| Export and paper fallback | Main host only; private export has enough records to continue on paper |
| Cleanup | Event deletion is deliberate; account/session cleanup does not delete canonical identities blindly |

Then rehearse approximately 50 player devices/sessions plus organisers and projector.
Check the venue’s actual reception, battery, data use, projector scaling and Auth
rate limits. Browser simulations and embedded database benchmarks do not prove
mobile reception or real Supabase concurrency. Keep the paper procedure ready.

Before the cadet event, verify every physical mission answer, lock, clue, phrase,
equipment checklist, scoring rule and timing. The starting mission descriptions
are editable examples, not a validated puzzle pack.
